hearty rules

Overview

hearty checks a mod for problems (lints) and rewrites its script files in one consistent style (formatting), on every core at once: even the largest Workshop mods take it seconds.

Install it with cargo install hearty, or download a binary from the latest release. Every example on this page is hearty's real output, regenerated whenever the rules change.

hearty                # lint the mod in this folder
hearty --fix          # remove redundant fields
hearty --format       # format its script files
hearty --check --lint # in CI: fail on unformatted
                      # files, missing localisation
                      # or redundant fields

Lints

hearty (or hearty --lint) runs every lint, and exits with an error when it finds missing localisation or redundant fields. It shows the first 10 findings of each kind in full, and counts the rest. Lints marked --fix are fixed by hearty --fix.

Formatting

hearty --format applies these rules, in the order listed (joining short blocks and normalising spacing in one pass), to the *.txt files under common/, events/ and history/, and hearty --check reports what they would change without writing, failing if any file would change. A file that doesn't parse, or isn't UTF-8, is left as it is. Every token and every word of every comment is kept, in order, and so are line endings and a leading BOM.

Options

Usage: hearty [OPTIONS] [PATH]. The actions are --lint (the default when none is given), --fix, --format and --check. Given together, they run in the order --fix, --format, --check, --lint, in one pass over the files on every core: each file is read once and written at most once. A file that can't be written is reported, isn't counted as fixed or formatted, and makes hearty exit with an error once everything else is done.
